# 公共后端与桌面移动客户端优化方案

> 选型更新：用户明确以算法研发为主要投入后，通用基础设施改为成套产品优先。技术选型以 [算法优先的成熟组件替代方案](algorithm-first-components-20261116.md) 为准：Supabase 替代本文独立 Keycloak/数据库/存储组合，成套沙箱优先于自管 gVisor。本文的资源隔离、幂等、共享协议与跨端验收要求继续有效；原选型保留供对照，不应同时部署两套身份或迁移系统。

日期：2026-11-16。状态：调研后的拟议设计，尚未实施。本文更新此前以“个人手机连接自己的电脑”为最终形态的设计前提；本地服务现在是公共产品的开发部署方式。

目标是同一套后端产品服务多个隔离用户，Electron 与 iOS、Android App 使用相同业务协议。用户本地测试只需要一个开发账号，两端登录即可；公开服务前必须自动验证多用户隔离。复用能力代码不等于共享私人数据，兼容后端升级也不等于客户端永远无需升级。

## 1 产品与架构决策

采用模块化后端、独立执行环境、共享客户端业务层。保留现有 Python Runtime、React、Electron、Capacitor；补齐身份、资源权限、事务持久化、协议与运行生命周期。不重写模型引擎，不在首版引入 Kubernetes、Kafka 或新的 Agent 编排框架。

“大家都是这么做”的准确理解是采用成熟的身份协议、数据库、接口契约、容器部署和隔离机制。不存在一个安装后就能自动让当前个人 Agent 系统成为安全公共服务的框架。以下技术选择是针对已有代码的工程判断，不是技术市场占有率排名。

```text
Electron                         iOS / Android App
    └──── 共享 TypeScript SDK、消息模型、状态处理 ────┘
                             │ HTTPS
                 统一 FastAPI 业务入口
               身份校验、资源授权、请求对账
                ├── Keycloak 身份服务
                ├── PostgreSQL 业务数据
                ├── 文件资产与模型凭据服务
                └── Runtime 生命周期协调
                      ├── 空间 A 的 Runtime 所有者
                      │      └── A 的受限工具执行环境
                      └── 空间 B 的 Runtime 所有者
                             └── B 的受限工具执行环境
```

这是职责图，不要求每个框都是一个微服务。业务 API、授权、资源目录、配置和操作记录先放一个模块化 FastAPI 服务中；身份服务、数据库和执行沙箱具有实际独立部署理由。

同一执行分区只有一个活跃 Runtime 所有者。原有“单 Runtime”要求保护的是同一份会话、审批 Future、调度和磁盘状态，不是要求全平台只能运行一个 Python 进程。首版每个个人空间使用一个独立 Runtime 分区；后续依据实测资源占用再细分。空闲环境可回收，但必须先持久化并确认没有活动回合、待审批或依赖进程内状态的任务。

## 2 推荐技术组合

| 部分 | 选择 | 选择理由与边界 |
|---|---|---|
| 手机客户端 | React + TypeScript + Capacitor，保留当前实现 | 已有两套原生工程和业务组件，当前问题主要不在 UI 技术栈；原生能力通过插件适配 |
| 桌面客户端 | Electron + React，增加明确远程服务模式 | 保留已有交互；远程模式不启动、回收端口或停止服务进程 |
| 业务后端 | 现有 FastAPI + Pydantic + Python Runtime | 接着使用已有引擎和工具，不改写为 Node、Java 或另一个 Agent 框架 |
| 登录 | Keycloak + OpenID Connect，授权码 + PKCE | 本地与公共部署均可使用同一身份协议；不自己编写密码、重置密码、令牌签发体系 |
| 业务数据库 | PostgreSQL + SQLAlchemy + Alembic | 事务、约束、版本迁移和权限适合操作对账及多用户资源归属 |
| 客户端协议 | 完整 Pydantic schema → OpenAPI → Hey API TypeScript SDK | 两端依赖同一协议包；SSE 事件另建明确模型，不能假定 HTTP SDK 自动覆盖事件语义 |
| 服务端数据缓存 | TanStack Query，逐个业务入口接入 | 用于会话列表、模型目录、任务和快照；流式消息由共享 reducer 更新同一份缓存 |
| 本地 UI 状态 | React 状态，桌面既有 Zustand 按需保留 | 草稿、面板和滚动属于客户端；不再另存一份会话事实源 |
| 事件传输 | 保留 HTTP + SSE | 聊天和任务通知先沿用已有链路；有证据需要双向低延迟的终端等通道再增加 WebSocket |
| 开发部署 | Docker Compose + 一键包装脚本 | 统一启动身份、数据库和服务；本地状态持久化，重启不重建账号 |
| 公共工具隔离 | Linux 上优先验证 gVisor/runsc | Shell、PTY、插件、浏览器必须通过兼容性及隔离测试；验证不过则换虚拟机隔离，不降级为宿主执行 |
| 文件 | 首阶段受控私有卷；公共资产接口兼容对象存储 | 用户工作目录保留 POSIX 语义，附件/导出物可存 S3 兼容对象存储；不把工作目录直接当对象存储挂载 |

Capacitor 明确支持以 Web 技术构建 iOS/Android 应用和接入原生 SDK。[官方介绍](https://capacitorjs.com/docs)。这支持保留当前技术路线，但不证明现有 App 已通过真机性能验收。

Keycloak 提供标准 OIDC 端点；原生应用推荐外部浏览器授权并使用 PKCE，而不是在应用 WebView 中收集用户密码。[Keycloak OIDC](https://www.keycloak.org/securing-apps/oidc-layers)、[RFC 8252](https://www.rfc-editor.org/rfc/rfc8252.html)。

FastAPI 的 OpenAPI 可以生成 TypeScript SDK；完整的请求与响应模型是前提。[官方 SDK 文档](https://fastapi.tiangolo.com/advanced/generate-clients/)。TanStack Query 面向远程数据获取、缓存与同步，适合替换当前散落的获取与刷新逻辑。[官方介绍](https://tanstack.com/query/latest/docs/framework/react/overview)。

SQLAlchemy 负责数据库访问，Alembic 负责版本迁移。[SQLAlchemy](https://docs.sqlalchemy.org/en/20/intro.html)、[Alembic](https://alembic.sqlalchemy.org/en/latest/)。具体版本在实现阶段锁定经过联调的一组受支持版本，不使用浮动 latest 镜像或因追新一次升级全部依赖。

### 为什么不直接换另一套全家桶

- Supabase 是合理备选，适合同时采用其身份、数据库、存储和实时能力的新项目；其自托管组件仍需自己部署维护。本项目已有 Python 执行系统，替换平台不会消除 Runtime 与沙箱改造，首选只增加必要组件。[自托管文档](https://supabase.com/docs/guides/self-hosting)。
- Keycloak 的代价是多一个身份服务及配置维护。将启动、realm/client 初始化和开发账号准备放入脚本，用户不需要日常进入管理后台。它解决登录，业务对象权限仍由后端实现。
- 不为“原生”二字改写 React Native/Flutter。先测键盘、长会话、代码滚动和内存；只有明确无法达标时才重新评估。
- 不引入第二套任务队列或工作流框架重写现有调度。先补持久化、所有者和恢复协议；将来需要多个调度实例时再依据实际负载选工具。

## 3 账号与资源隔离

首版每个用户自动创建一个个人空间。界面不要求用户理解租户或手工创建空间。预留成员关系可避免以后团队协作推倒数据模型，但首版不交付邀请、组织后台和复杂角色编辑器。

身份以 OIDC issuer + subject 关联内部 user_id，不以邮箱或设备名称作为永久主键。客户端可以选择 workspace_id，服务端必须校验 membership；客户端提交 user_id 不能改变请求执行身份。

| 对象 | 归属 |
|---|---|
| 账号与身份 | 身份服务保存登录资料；业务服务保存用户映射与空间关系 |
| 会话、回合、消息、审批、任务、自动化、用量 | 空间；每次读写、订阅、导出和控制都校验 |
| 项目与工作目录 | 空间下的项目；客户端使用 ID，不提交宿主绝对路径 |
| 附件、截图、导出物 | 空间及关联资源；下载前授权，分享另走明确授权流程 |
| 用户模型/MCP/Git 凭据 | 空间内秘密引用；客户端只见是否配置，不见密钥值 |
| 平台模型密钥 | 平台秘密管理；租户 Runtime 和工具不能读取原始平台 Key |
| 浏览器 Cookie、登录态、PTY | 所属执行环境；禁止跨空间复用 |
| 私人记忆与扩展配置 | 空间；公开技能目录不包含私人内容或凭据 |
| 设备 token、草稿、布局、缓存 | 设备，且以服务 ID + 用户 + 空间划分 |

API 对象授权与数据库行级权限共同保护业务数据。PostgreSQL RLS 可按行限制访问，但表所有者和 BYPASSRLS 角色可能绕过，因此应用角色不能用数据库管理员权限，连接池中空间上下文应按事务设置并清理。[PostgreSQL RLS](https://www.postgresql.org/docs/current/ddl-rowsecurity.html)。对象 ID 难猜不能代替访问控制。[OWASP 对象授权](https://api-security.owasp.org/editions/2023/en/0xa1-broken-object-level-authorization/)。

退出账号或切换服务时，取消所有请求和 SSE，清除该会话凭据与内存缓存，隔离或删除离线内容，注销推送绑定。迟到的响应必须同时校验连接代次、用户和空间，不能仅比较 thread_id。

### 登录与撤销语义

Electron 和 App 是两个 OIDC public client，分别配置回调与 PKCE，不在包内保存 client secret。使用系统浏览器；桌面令牌由主进程保管，手机使用系统安全存储。API 校验签名、issuer、audience、有效期及业务设备会话。

刷新令牌轮换，刷新并发合并；刷新失败回到登录，不循环发送操作。设备撤销需要 API 检查业务会话状态，主动关闭该会话事件流。不能只撤销 refresh token，却宣称已经签发的长效 access token 立即失效。

## 4 执行权限与公共服务边界

身份隔离、目录隔离、工具执行隔离是三层不同的要求。登录框架不限制 Shell；工作目录设置不防止绝对路径访问；多个 Python 进程仍可能属于同一个宿主用户。

推荐公共服务将可信 Runtime 控制逻辑与不可信执行动作分离。Runtime 管理模型交互、状态、审批与调度；Shell、终端、下载的插件代码、MCP 子进程及浏览器在空间隔离环境运行。Python 进程内执行的插件也必须纳入迁移清单，不能只隔离 exec_command。

在 ToolRuntime 的已有执行边界增加远程沙箱适配，不把聊天引擎重新实现一遍。公共模式关闭能直接落到宿主机的旧路径；不支持的工具返回明确原因。沙箱不挂载 Docker socket、平台配置目录、个人 HOME 或其他用户卷；设置资源与网络边界，阻止访问云元数据和内部管理端点。

gVisor 提供 OCI runtime 并可与现有容器工具结合，但并不支持每个 Linux 行为，官方明确要求实测兼容性。[机制](https://gvisor.dev/docs/)、[兼容性](https://gvisor.dev/docs/user_guide/compatibility/)。需要覆盖 node-pty、Git/SSH、浏览器、MCP 子进程、文件监听和退出清理。macOS 本地原生运行通过，不代表 Linux 公共沙箱通过。

平台模型调用由可信服务注入平台 Key；工具环境拿不到它。Runtime 使用受空间、模型、额度和有效期约束的调用权限。用户自己的凭据也按需要注入最小范围，不能把全部 providers/env 配置复制给所有子进程。

“自动批准”只影响空间允许的操作，永远不能提升为公共服务器管理员权限。客户端选择是策略请求，服务端返回有效策略；最终决策由服务端持久化。终端绕过 Agent 审批的现有行为必须成为独立、明确的权限，不能因为能聊天就能开终端。

云端 CUA 控制隔离虚拟桌面，不控制公共宿主桌面。用户自己的电脑文件和桌面是未来可选的本地执行节点，需另行绑定授权；公共版不隐含拥有这些权限。

## 5 数据与运行状态的迁移

现有 ThreadStore 使用 JSON/JSONL，原子写单个文件不等于多对象事务。公开版需要可靠的操作对账，不能只在网关加一个 request_id 后继续让内部重复创建 turn。

按两步迁移，任何阶段都不维护两份可以同时修改的事实源：

1. 开发过渡阶段：PostgreSQL 保存用户、空间、资源归属、执行分配；旧 Runtime 仍持有自己隔离目录内的会话。会话索引是可重建投影，不能从索引反向覆盖 Runtime。此阶段不宣称完成公共发布要求。
2. 公开前：抽取现有存储调用边界，为云端模式增加 PostgreSQL 实现，迁移会话、turn 预留、操作记录、待处理决定及必要调度状态。创建幂等记录、分配 turn 和持久化受理状态必须处在同一事务边界；进程启动由提交后的待执行记录触发，恢复时按记录对账。文件与大附件仍在卷/对象存储。旧文件模式只用于明确的旧部署和离线 fixture，不做持续双写。

关键关系为 users、workspaces、memberships、projects、threads、turns、items、operations、decisions、assets、runtime_leases、automation_runs。共享资源外键要防止引用另一空间的对象，不只在读取时过滤。

第一阶段只运行一个协调者；每个 Runtime 分区设置唯一所有权和续租。公开扩容需要有 fencing 的所有权检查，旧进程失去所有权后不得继续写入或执行。FastAPI 多 worker 不共享普通内存，不能靠增加 API worker 来复制带 Engine 和审批 Future 的应用实例。[部署说明](https://fastapi.tiangolo.com/deployment/concepts/)。

不尝试持久化 Python Future。持久化的是待审批事项、运行阶段和已完成动作；重启后重新建立等待关系，无法安全恢复的回合标记中断并解释已有副作用。

调度系统只有一个权威入口。任务和自动化的到期记录、领取、运行归属需要持久化与去重；环境空闲回收不能导致自动化永远不触发。首版固定在线执行者验证恢复，再实现按需启动和过期触发策略。

## 6 命令、事件与跨端一致性

### 命令与幂等

发送、审批、创建任务、上传完成和其他关键写操作携带 client_request_id。唯一范围至少包含空间、操作类型和请求 ID，并保存规范化请求指纹。相同 ID/相同内容返回同一结果，相同 ID/不同内容返回冲突。

断线后查询 operation 状态。状态至少区分未受理、已受理、执行中、完成、失败和结果待确认；在无法判断时不能自动重放。幂等去重不等于外部工具恰好执行一次：发邮件、外部提交等副作用要使用对方幂等能力或记录后人工核对，不能承诺跨系统事务。

修改模型/配置使用 revision，冲突后重新获取并保留用户编辑值供选择。审批使用稳定 decision_id 和条件更新，首个有效决定生效，另一端显示已处理而不是再次操作。

### 快照与事件

共享 reducer 负责 message/item/turn/decision 的事件归并，两端调用同一实现。使用 snapshot + cursor + SSE；去重、旧事件忽略、保留未知事件降级记录，发现游标过期重新拉快照。

保留原 Runtime 全局 seq 语义，线程事件之间允许跳号。公共协议游标包含来源/代次与位置，不能把不同 Runtime 的 seq 直接比较。新增空间活动流用于会话列表和待办摘要，不能只监听当前会话。

SSE 用于服务端到客户端的事件流。[MDN](https://developer.mozilla.org/en-US/docs/Web/API/Server-sent_events/Using_server-sent_events)。保留当前可附 Authorization header 的流式读取方式；代理禁用不合适的缓冲，配置心跳、连接期限和重新鉴权。推送只提醒发生变化，进入 App 后以服务端同步结果为准。

缓存 key 至少带 service_id、user_id、workspace_id 和资源 ID。TanStack Query 不会自动解决 SSE 次序或业务冲突；这些规则仍在共享 reducer 中验证。禁止它或传输层自动重试未知结果的 mutation。

### 协议维护

先补齐实际路由的请求/响应 schema，再生成 SDK，禁止直接把当前不完整的 OpenAPI 快照视为完整合约。稳定 operation_id、错误 code 和事件版本；业务功能以 capabilities 返回状态及原因，区分不可用、未配置、无权限和版本不支持。

内部 Runtime token、legacy 管理入口和任意 IPC 不暴露到公共入口。新接口只开放明确业务操作。后端优先做兼容性新增；破坏性变更发布新协议版本，并对当前及前一受支持客户端版本做回归。

## 7 模型配置

空间默认值 → 会话选择 → 本轮显式覆盖，服务端计算并返回实际执行配置。服务端校验 provider/model/effort 的组合与用户权限；不可用时明确报错，不静默换模型、关闭思考或缩短输出。

模型目录返回真实可用 ID、显示名、配置状态、支持的推理档位、附件能力及允许限制。用户可以修改模型；平台安全和额度约束仍由服务端执行。运行中修改默认影响下一轮，本轮记录保持不变。

UI 显示选择是否已保存和本轮实际使用模型。取消编辑不改变持久配置；其他客户端更新时，未编辑的本地值跟随，正在编辑的值提示冲突，不无声覆盖。

平台提供模型与用户自带 Key 可使用同一调用合约，按凭据来源区分。首版本地开发可以只配置已有提供商，不因此锁死协议。真实模型凭据留在服务端；自动验收默认离线 provider，付费调用只做明确有界冒烟。

## 8 手机与桌面的功能交互

基本产品能力以服务端相同操作、相同输入语义、相同权限和相同结果定义，不以页面数量或按钮位置定义。

| 流程 | 两端共同语义 | App 的交互 |
|---|---|---|
| 登录 | 同一身份服务、独立设备会话 | 首屏登录；本地测试地址放开发连接入口 |
| 会话 | 创建、搜索、归档、分叉与继续使用同一服务 | 手机抽屉/列表；运行与待处理状态可见 |
| 发送 | 同一命令结构，提交后由服务端持有 | 正常发送、运行中补充和停止明显区分 |
| 模式 | 同一能力与策略 | 模式集中到输入设置；附件菜单移除模式按钮 |
| 模型 | 同一目录与配置优先级 | 点击模型名选择；仅显示支持的参数 |
| 附件 | 上传形成 asset_id，服务端统一解析 | 文件卡展示上传/解析状态；手机选择与服务端引用分开 |
| 消息 | 共享最终答案、过程、诊断、子代理转换 | 正文优先，过程展开；不丢正文、不暴露原始 JSON 代替产品展示 |
| 审批追问 | 权限范围、稳定 ID、单次有效决定 | 底部卡或详情；显示所属任务及另一端处理结果 |
| 任务目标 | 共用状态机与暂停/继续协议 | 待处理优先，详情跳回原会话 |
| 文件 Git | 同一项目资产和变更语义 | 文件差异全屏查看，提交等写操作显示明确对象和结果 |
| 终端浏览器 | 所属隔离环境、控制权与生命周期一致 | 按需进入；展示执行位置，触控适配 |
| 设置 | 空间配置、账号安全、设备偏好分开 | 普通用户看不到平台管理配置 |
| 通知 | 服务端任务事实不依赖客户端在线 | 后台推送不含敏感正文；点击后鉴权再拉状态 |

草稿默认设备本地；主题、滚动和展开状态不跨端强制同步。用户在自己的同一空间继续会话属于授权同步，不意味着不同用户共享数据。

断线交互分别表示“尚未发送”“请求结果待确认”“服务重连中”“授权过期”“执行环境启动中”。停止点击后展示“正在停止”，收到服务端确认再改变状态。离线不执行草稿，也不把发送按钮变成无提示的离线队列。

附件统一采用元数据加资源 ID 的命令结构；解析由后端完成，正文预览用于用户检查，不再由某个客户端自行重复拼入提示词。上传协议检查所属空间和会话，完成失败可清理孤立资产，但移除引用不直接删除其他会话正在使用的资产。

本地通知不是可靠后台推送。公网发布阶段需要 APNs/FCM 的服务端投递与用户设备绑定；未完成时界面应明确后台提醒限制，不以“任务页已实现”代替通知链路。

Electron 远程模式让 UI 资源保持本地打包，IPC 仅提供必要平台能力。生成的 HTML、用户网页和文件预览不能进入拥有凭据/原生桥权限的主界面上下文。[Electron 安全建议](https://www.electronjs.org/docs/latest/tutorial/security)。

## 9 本地只用一个账号的具体体验

拟交付一个 `npm run dev:stack` 包装入口，同时提供可双击启动器；这是计划命令，目前不存在。启动器负责检查依赖、Compose 服务启动、数据库迁移、开发身份初始化和健康检查。Compose 支持用一个配置统一管理多服务、网络和卷。[Docker 文档](https://docs.docker.com/compose/)。

首次启动自动创建一个普通用户 `dev@example.test` 和个人空间，随机生成开发密码，保存在忽略提交的开发凭据文件中并显示读取位置。重启不重设密码、不重建用户、不清空会话；专门的开发重置动作才重置。开发账号不是 Keycloak 管理员，平台管理员凭据单独保管。

用户只做：启动 → 用这个账号登录 Electron → 同一账号登录 App → 测试。无需注册邮箱、手动建租户、复制 Runtime token 或进入身份服务后台。Keycloak 配置可初始化导入，重复启动应避免覆盖现有 realm 和用户。[初始化文档](https://www.keycloak.org/server/importExport)。

本机桌面调试和真机调试使用同一套协议。真机不能访问手机自己的 localhost；启动器提供一次性设置的可达开发地址，API 和 OIDC issuer 使用双方均可访问、证书受信任的主机名。开发连接二维码只携带公开地址和环境信息，不携带平台管理 token、上游 Key 或固定账户密码。不会为方便连接禁用发布版 TLS 校验。

需要 Docker 等依赖时先给清晰检查结果，不在失败时自动改成无鉴权服务。本地快速模式可运行单个可信开发 Runtime；它用于功能调试，不构成公共沙箱验收。Linux 隔离验证在专用测试环境中执行。

默认离线 fixture 提供可重现的发送、工具、审批、错误和恢复场景；用户手动测试真实模型时使用正常配置，不受累计 6 次之类冒烟配额限制。自动化付费测试仍严格有界。

另一个测试账号只由测试程序创建、验证后清理，用户不需要登录它。生产配置拒绝开发 seed、已知测试凭据、无鉴权启动和本地调试权限。开发初始化不接触个人 `~/.deepseek`，不导入现有私人历史。

## 10 现有代码的具体改造顺序

| 位置 | 处理 |
|---|---|
| `scripts/live-preview.py`、`live_policy.py` | 保留为有界冒烟工具；日常服务使用正常配置加载，移除 personal 对预览客户端的依赖 |
| `scripts/start-runtime.mjs`、`companion-env.mjs` | 开发启动纳入统一服务配置；helper 构建成版本化产物，避免靠相邻源码目录猜路径 |
| Runtime `server/auth.py`、`mobile/devices.py` | 区分 OIDC 用户与旧个人设备授权；云端关闭旧管理员直连和配对入口，旧模式不伪装为多用户 |
| Runtime `server/routes.py`、`mobile/*` | 逐路由补资源归属校验、公开 schema 和能力状态；保留受控业务操作，禁止通用转发 |
| Runtime `threads/store.py`、`manager.py` | 存储边界与操作事务；所有权、恢复、审批事实和副作用对账 |
| Runtime 工具/扩展执行入口 | Shell、PTY、插件、MCP、浏览器全部纳入沙箱执行清单；发现宿主回退即阻止公共发布 |
| `src/protocol.ts` | 抽出共享传输与事件模型；类型由合约生成，业务 reducer 单独测试 |
| `src/conversation.ts` 与桌面 `agent/deepseek-runtime.ts` | 提取无 Electron 依赖的消息转换；导入历史、最终回复、诊断和子代理统一 |
| `src/main.tsx` | 按登录连接、会话状态、输入、审批、资源导航拆职责；先迁移业务逻辑，再改布局 |
| `src/model-catalog.tsx` | 支持有效配置、能力参数、保存/冲突与下一轮生效 |
| `src/media-composer.tsx`、桌面 FloatingComposer | 共享结构化输入，不再各自拼接附件上下文 |
| Electron 生命周期与 IPC | 远程模式不抢端口、不重启服务；保留录音、选择文件、通知等平台接口 |
| 原生凭据、通知与连接恢复 | 设备会话撤销、账号隔离缓存、真实恢复和推送绑定 |

共享代码独立形成带版本的包，两个项目均依赖它，不复制源码或强制合并整个仓库。初期只需要协议 SDK 与客户端业务核心两包；UI 暂不强行共享。原 Runtime 以固定版本 Python 包/镜像交付，Node helper 同一发布清单记录版本与哈希。

## 11 阶段交付与验收

| 阶段 | 完成结果 | 验收依据 |
|---|---|---|
| A 契约与执行边界 | 实际路由清单、宿主动作清单、模型配置规则、共享消息样例 | 覆盖桌面和 App 主要路径；未知项列出，不能直接标全部兼容 |
| B 本地单账号闭环 | 一个开发账号，两端远程模式登录、模型可选、发送审批恢复 | 离线真实 Runtime 路径通过；关闭桌面后任务仍可用；账号重启保留 |
| C 多用户与执行隔离 | 授权、沙箱、操作事务、持久化及恢复 | 测试账号 A/B 交叉访问被拒；沙箱越界测试通过；不暴露宿主权限 |
| D 跨端功能与手机交互 | 共享状态/消息/输入，两端相同基本能力 | 相同事件样本得到相同业务结果；手机键盘、长列表、附件与切后台通过 |
| E 公共预发布 | HTTPS、备份恢复、限额、审计、通知、升级回滚 | 升级和断网演练、权限撤销、负载与资源测量；再开展正式打包发布 |

阶段 B 是方便用户持续验证的第一个可用交付，不宣称完成 C/E。功能框架实现不等于公共服务上线。

核心自动验收：

1. A/B 账号互换会话、文件、审批、终端、截图和 SSE 资源 ID，均不能越权。
2. A 在 Electron 发起任务，App 看到相同内容与模型，能完成同一审批。
3. 桌面修改模型，手机未编辑时跟随；正在编辑时明确解决冲突。
4. 注入已提交但响应丢失、重复请求、服务重启、并发审批；不重复创建回合或重放未知副作用。
5. 当前会话之外的新任务、会话和待办能同步；游标重放、跳号、代次变化不串流。
6. 切换账号后缓存、草稿、未完成上传和迟到响应不泄露到新账号。
7. Shell、PTY、插件、MCP、浏览器不能访问别人的卷、宿主凭据、内部管理网络或云元数据。
8. 迁移前后 fixture 会话、turn 和消息数量及语义一致；备份可恢复，活动任务升级前先排空或明确中断。
9. 数据库写入与启动间崩溃能恢复；旧所有者被 fencing 后不能继续动作。
10. iOS/Android 真机上登录回调、安全存储、中文输入法、长消息、断网、上传、通知及恢复正常。

成本与性能用真实测量决定：记录每个活跃空间的 Runtime/浏览器内存、冷启动时间、流式延迟、文件量、模型调用与任务并发。初始限额由配置明确设置；没有测量前不承诺具体用户容量，不为假设的大流量预先增加分布式设施。

## 12 研究与验证边界

源码观察：现有移动与桌面调用链、Runtime 鉴权/会话存储、工具和终端入口、配置/构建脚本及已有测试已作针对性核对，未逐行审完所有引擎、插件及 OS 实现。前轮已定向复现预览参数覆盖、旧模型状态、导入消息分类差异；完整回归因本地依赖不全未完成，历史通过记录不能替代新版本验收。

本轮研究依据为上文官方文档，技术组合及迁移顺序是结合现有代码提出的设计。尚未部署 Keycloak/PostgreSQL、创建开发账号、替换存储、运行公共沙箱、验证跨端完整链路或发布商店版本。实现前还需完成阶段 A 的全入口归类和隔离兼容性试验。

本方案没有迁移、覆盖或上传用户已有数据，也不要求为了开发初始化读取真实模型密钥。完整实现的完成标准是上述可重复验收结果，不是目录、依赖或登录页面存在。
