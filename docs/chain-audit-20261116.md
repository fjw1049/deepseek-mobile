# 手机完整链路审核 · 2026-11-16

## 结论

复用同一个电脑 Python Runtime、手机通过受限 HTTP/SSE 控制的方向合理；前端、会话/审批/工具仍共用原引擎。当前不能认定“所有功能都可用”或达到商店发布条件。此前离线主链路通过，没有覆盖个人服务传输限制，导致真实使用仍报错。

## 本次确认及修复

1. **个人模式误用冒烟输入上限（高优先级）**：`scripts/live-preview.py` 中个人模式仅豁免累计次数，仍执行 250,000 字节限制，模型、输出和输入错误共用一句英文。现有服务只读检查确认为 personal，失败会话连续三轮留下同一句错误。独立临时 Runtime 离线测得短问候的完整请求为 123,789 字节，其中工具定义约 62,354 字节；所以消息长度远小于实际请求大小。并未保存或重放用户的真实完整失败请求，不能声称测得了它的精确大小。
   - 分离个人与冒烟策略：个人 16 MiB、冒烟保持 250 KB；固定模型、1024 输出限制、6/12 次冒烟额度及禁止自动重试均保留。
   - 逐项中文报错；超限拒绝发生在计数和上游网络调用之前。16 MiB 是本地请求保护，不代表模型上下文 token 上限，也不保证五个大附件能一次发送。
   - 抽取原传输类并使用 httpx.MockTransport，验证 300 KB 历史请求在个人模式通过、冒烟拒绝；额度仍生效，无真实付费调用。
2. **系统失败记录冒充答案（中优先级）**：Runtime `_attach_completion_note` 在没有模型答案时也生成带 final_answer 标记的 agent_message。原前端将其当作答案，产生截图中的大段核验 Markdown 和复制按钮。
   - 按 Runtime 的 `completion_note` 元数据拆分，只移除匹配的末尾注记；真实部分答案保留。系统记录仍可展开查看，复制只包含模型正文。
   - 失败显示简洁中文建议，不自动重发；未知错误提示先核查已有结果，避免重复副作用。

## 仍需处理的产品缺口（源码观察/未完成）

- **模型能力与控件未完全对齐**：通用客户端可编辑提供商、模型、推理强度；当前 personal 服务固定 flash 且强制关闭思考。设置页已明确限制，但仍需服务能力协商并约束模型选择器，不能把任意选项当成可用。1024 输出上限也只适合有限回复，长文/代码任务可能截断。
- **上线前必须完成统一幂等和对账协议**：当前避免自动重试未知写操作；这不等于所有旧接口已经具备可安全重试的协议。
- **真机能力**：真实 ASR 依赖电脑凭据；Keychain/Keystore、系统分享、中文键盘、后台/前台恢复和断网需真机验收。
- **通知**：只有本地事件通知，尚无可靠 APNs/FCM 后台推送。
- **个人服务持久部署**：当前沿用 `/tmp/deepseek-mobile-full-live-20261115`，临时目录不适合作为最终持久部署。迁移需单独执行一致性备份和停机迁移，本次保留现有配对/会话而未迁移。
- **原生安装/发布**：工程同步不等于手机安装更新，更不等于签名上架。
